# Native OCaml OpenTUI

This repository is the native OCaml side of an OpenTUI frontend. The target is a direct OCaml-to-Zig boundary; JavaScript is not an intermediate runtime.

The current architecture and open decisions are in [`design.md`](design.md),
and the implementation sequence is in [`plan.md`](plan.md). The pinned
upstream OpenTUI source is documented in [`vendor/README.md`](vendor/README.md).

For a fresh checkout, initialize the pinned upstream source with:

```sh
git submodule update --init --recursive
```

The repository is organized as a Dune monorepo. Local packages live under [`packages/`](packages/), while external OCaml dependencies are resolved by Dune's package-management mode. The first package is [`opentui-raw`](packages/opentui-raw/), which establishes the narrow native boundary before any retained-tree or reactive UI layer is added.

## Development

Enter the development environment with:

```sh
nix develop
```

The default shell includes the compiler, Dune, formatter, LSP, documentation
tools, and Zig 0.16.0, which is the version currently accepted by the pinned OpenTUI
native build. Use `nix develop .#test` for the smaller CI/test shell.

Then run:

```sh
dune pkg lock
dune build @check
dune runtest
```

`dune.lock` is generated by Dune and should be reviewed as part of dependency changes. It is intentionally not ignored by Git.

## Package direction

The initial package graph is described in [`packages/README.md`](packages/README.md). Package boundaries follow independently useful dependency layers, not individual Zig source files. The reactive and widget layers remain future packages until the native ownership and update contracts are stable.
